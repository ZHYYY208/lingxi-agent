# 灵犀企业知识库智能体：产品与技术白皮书

版本：v1.0 · 更新日期：2026 年 9 月

## 产品概述

灵犀是一款面向企业内部文档的问答助手。它将分散在制度文件、产品手册、项目复盘和经营报告中的知识统一接入，通过检索增强生成（RAG）与多工具调用，为员工提供带出处、可追溯的回答。系统既支持私有化部署，也支持在云端租户中运行。

灵犀的目标不是替代搜索框，而是把「找文档、读文档、核对口径、汇总结论」这一整套工作压缩到一次对话中。每条关键结论都会附带文档片段引用，用户可以直接展开原文核对，降低大模型幻觉带来的风险。

## 知识处理链路

文档上传后，系统首先进行格式识别与文本抽取。当前支持 PDF、Word（DOCX）、Markdown 和纯文本。扫描版 PDF 需要先进行 OCR，否则系统会提示未提取到有效文本。系统会过滤空内容、去除不可见字符，并按标题和段落保留文档结构。

文本切分采用语义优先的固定窗口策略：每个片段目标长度为 512 个字符，相邻片段重叠 64 个字符。优先在句号、问号、分号和换行处切分，过长句子再按窗口硬切。重叠区用于保留跨片段的上下文，避免一个完整规则被截断后无法召回。每个片段还会记录来源文档、章节标题、页码和片段序号。

系统使用嵌入模型将片段编码为向量并写入向量库。生产环境默认使用 Milvus 管理向量索引，开发环境可以回退到本地 SQLite 索引。文档元数据、聊天会话和反馈记录存储在 MySQL；本地演示模式使用 SQLite。会话上下文会同步缓存到 Redis，服务因此保持无状态，可以水平扩容。

## RAG 检索链路

用户提问后，查询先经过多轮上下文改写。例如用户先问「年假怎么申请」，再问「那超过五天呢」，系统会把上一轮问题与当前追问组合成完整检索意图，避免指代丢失。

检索阶段同时运行两条召回链路。向量检索负责语义相似度，BM25 负责关键词与专有名词的精确匹配。两路各召回约 24 个候选片段，使用 Reciprocal Rank Fusion（RRF）融合排名，再用轻量级重排器综合向量分、BM25 分、查询词覆盖率、标题匹配和连续短语命中进行精排，最终保留 Top-5 片段。系统会限制同一文档最多入选两个片段，以提升证据多样性。

如果最高相关度低于阈值，系统不会强行拼凑答案，而是明确告知知识库中缺少直接依据，并建议补充文档或换一种问法。这一「证据不足即拒答」策略是企业场景降低 AI 乱答率的关键。

## Agent 与多工具调用

灵犀的 Agent 采用「规划 - 执行 - 观察 - 核验 - 生成」的状态图编排。规划节点先判断问题类型：制度流程类问题优先检索知识库；涉及销售额、订单、环比等指标时调用只读经营数据库；需要外部实时信息且用户明确要求时调用联网搜索。对于复合问题，可以依次调用多个工具。

工具调用并不是让模型直接执行任意 SQL。数据库工具只接受受控的指标、区域、季度和维度参数，由后端生成参数化查询。这样既保留了自然语言查询的便利，也避免注入风险和越权访问。联网搜索支持 Tavily 或 DuckDuckGo，结果会与内部证据分开标注。

执行轨迹会通过 SSE 实时推送到前端，包括检索耗时、召回数量、最高相关度、数据库查询条件和工具状态。用户看到的不是黑盒式「正在思考」，而是可检查的执行过程。最终回答要求引用知识库片段编号，并说明经营数据的来源表。

## SSE 流式服务

后端使用 FastAPI 提供接口。聊天接口采用 Server-Sent Events 推送事件，事件类型包括 meta、status、tool、citations、token、done 和 error。前端通过 fetch 的 ReadableStream 解析 SSE，在保留 POST JSON 请求能力的同时支持鉴权头部。

典型首字延迟约为 0.6 秒；事件会先发送会话信息与规划状态，再逐步推送工具结果和答案 token。服务端对 SSE 设置 `X-Accel-Buffering: no` 和禁用缓存，确保在 Nginx 等反向代理后仍然逐字输出。

系统接口支持 API Key 鉴权、按客户端限流、结构化 JSON 日志和统一错误处理。每次请求带有 X-Request-ID，便于在日志平台关联排查。健康检查同时报告数据库、Redis、向量库和模型服务的状态。

## 部署架构

推荐生产架构包括：FastAPI 应用容器、MySQL 8、Redis 7、Milvus 2.4、对象存储（保存原始文件）以及可选的模型网关。Docker Compose 可一键启动演示环境，生产环境建议使用 Kubernetes，并为应用配置至少两个副本。

本地演示无需安装任何外部服务。系统会自动使用 SQLite 保存文档与会话、使用本地哈希嵌入和本地向量索引完成检索。Redis 与 Milvus 未配置时会自动降级，并在系统信息中明确显示当前模式。联网搜索默认关闭，避免在无 API Key 状态下发起不可控的外部请求。

若配置了大模型 API（兼容 OpenAI Chat Completions 协议），系统会在检索完成后调用模型生成答案。没有配置密钥时，系统使用本地证据抽取引擎：从高相关片段中选择关键句，按章节组织并附带引用，仍能完成可验证的问答演示。

## 文档与权限边界

上传文件大小默认限制为 25 MB，单次最多 10 个文件。系统会校验扩展名、文件大小和内容哈希，重复文档不会重复入库。原始文件保存于受控目录，下载接口返回原始文件名。

企业版支持部门空间、文档级权限和审计日志。演示版未接入组织架构，默认所有访问者共享一个知识空间。开启 API Key 后，所有 API 请求必须携带 `X-API-Key` 或 Bearer Token。

## 常见技术问题

**为什么片段是 512 字，而不是按 token？** 字符窗口更容易与中文文档结构对齐，也方便控制展示长度；在嵌入模型侧仍然会按模型要求转换。对于英文技术文档，可以调整为按 token 切分。

**为什么不只使用向量检索？** 制度文档中有大量专有名词、编号和精确条款，BM25 对这类关键词更敏感；向量检索擅长语义近似。混合召回配合重排，在中文企业文档上通常更稳定。

**如何评估效果？** 建议维护一组真实问题与标准答案，使用 Recall@K、MRR 和人工可答率评估检索，再分别统计答案忠实度、引用准确率和拒答率。上线前至少覆盖制度、产品、数据和权限四类问题。

**系统能否接入内部 SSO？** 可以。API 层目前提供 API Key，生产环境可在网关接入 OIDC/SAML，并把用户与部门信息传递给文档权限过滤层。
